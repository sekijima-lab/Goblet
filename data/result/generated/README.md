# Generated molecules for the eight DUD-E targets

This directory contains the complete set of molecules generated by Goblet for
the eight targets of the DUD-E diverse subset, as reported in the paper. It is
the experimental record behind Table `tab:pic50_improvement`, Figure 2 and
Figure 5.

## Contents

| path | contents |
|---|---|
| `d1/`, `d2/`, `d3/` | 40 CSVs each: one per target and array task, exactly as written by the optimizer |
| `generated_molecules_with_properties.csv` | all 42,936 records in one table, with computed physicochemical properties and structural-alert flags |

## What a "run" is

Each search was submitted as a five-task array job, and the three directories
`d1`, `d2`, `d3` are three submission batches of the same campaign. A **run**
is one array task pooled over the three batches: run *k* for a target is

```
d1/<target>_k.ASBOLTZ.csv + d2/<target>_k.ASBOLTZ.csv + d3/<target>_k.ASBOLTZ.csv
```

There are therefore five runs per target. The five runs sum to the per-target
record counts reported in the paper (AKT1 5,110; AMPC 7,112; CP3A4 5,094;
CXCR4 4,000; GCR 4,458; HIVPR 5,277; HIVRT 5,091; KIF11 6,793).

The consolidated table carries `batch` and `run` columns so either grouping can
be reproduced.

## Columns of `generated_molecules_with_properties.csv`

| column | meaning |
|---|---|
| `target` | one of akt1, ampc, cp3a4, cxcr4, gcr, hivpr, hivrt, kif11 |
| `batch`, `run` | submission batch (d1/d2/d3) and array task (1–5) |
| `source_row` | index within the originating CSV |
| `SMILES` | as written by the optimizer |
| `canonical_smiles` | RDKit canonical SMILES |
| `Step` | fragment-level MCTS iteration at which the molecule was retained |
| `Sim` | ECFP4 similarity to the initial molecule |
| `Reward` | search-time affinity reward, equation (1) |
| `delta_pic50_search` | `3 × Reward`; the search-time improvement in predicted pIC50 over benzene |
| `ReBoltz` | raw Boltz-2 affinity output from the post-search re-evaluation |
| `predicted_pic50_reevaluated` | `6 − ReBoltz` |
| `ReVina` | AutoDock Vina score from the post-search re-evaluation |
| `MW`, `heavy_atom_count`, `cLogP` | RDKit `Descriptors.MolWt`, heavy-atom count, Wildman–Crippen `Crippen.MolLogP` |
| `SAS` | Ertl–Schuffenhauer synthetic accessibility score |
| `PAINS_flag`, `BRENK_flag`, `NIH_flag` | true when the molecule matches at least one alert in that RDKit filter catalogue |
| `free_thiol`, `N_S_bond`, `aziridine` | SMARTS substructure hits |

## Two things to know before using these numbers

**The search reward and the re-evaluation are not the same protocol.** The
search-time reward (`Reward`, and hence `delta_pic50_search`) was computed with
the pocket constraint applied and with the Boltz-2 inference seed fixed to 42.
The re-evaluation (`ReBoltz`, and hence `predicted_pic50_reevaluated`) was
computed **without** the pocket constraint and **without** a fixed seed. Values
from the two are not interchangeable.

**One record has no re-evaluated value.** `ReBoltz` is empty for a single AMPC
record, which is why the paper reports 42,935 molecules for the improvement
rate while this table has 42,936 rows. Properties are defined for all 42,936.

## Provenance

- Boltz-2 version 2.2.1 (pinned in `env.yaml` at the repository root).
- Input sequences, MSAs and YAML templates: `data/sample_yamls/`.
- Fragment-generation model weights: `ckpt/pretrain/ver2/`, epoch 20
  (`feature-extractor-ep20.pth`, `node-header-ep20.pth`, `edge-header-ep20.pth`).
- Search entry point: `0_generate.job.sh`, which runs
  `Generator/mcts.py` with `mcts.reward_name="ASBoltz"` and `mcts.n_step=1000`.
