# MLflow security update: validation

Goblet's environment pinned MLflow 2.11.3. This update selects MLflow 3.16.1
to address the upstream security advisories affecting the old release,
including [CVE-2025-15036](https://github.com/advisories/GHSA-vhcx-3pq2-4fvc),
[CVE-2026-2651](https://github.com/advisories/GHSA-8c7q-86fq-vvmh), and
[CVE-2026-64849](https://github.com/advisories/GHSA-7gwp-5pfp-969j).
These advisories include server features; this does not establish that
Goblet's local training workflow was exploitable through those features.

## Compatibility decision

`Model/train.py` explicitly logs to `file://<project>/mlruns`. MLflow 3.16.1
rejects that backend by default. The training function therefore sets
`MLFLOW_ALLOW_FILE_STORE=true` only when the caller has not already set it.
An explicit `false` remains effective. The existing location, run IDs,
artifact layout and logging API calls are retained; no user data is migrated.

The file backend is in maintenance mode. This opt-in retains Goblet's current
workflow while upgrading MLflow, but a separate migration to SQLite should be
planned. See the official [file-store migration guide](https://mlflow.org/docs/latest/self-hosting/migrate-from-file-store/).
CLI users browsing existing logs must also explicitly opt in to file storage:

```sh
MLFLOW_ALLOW_FILE_STORE=true mlflow server --backend-store-uri ./mlruns
```

## Reproduce the checks

Use a new Python 3.10 environment. These commands do not install into an
existing research environment:

```sh
uv venv --python 3.10 /tmp/goblet-mlflow-validation
uv pip install --python /tmp/goblet-mlflow-validation/bin/python \
  -r tests/requirements-mlflow.txt
/tmp/goblet-mlflow-validation/bin/python -m unittest discover -s tests -v
uv pip check --python /tmp/goblet-mlflow-validation/bin/python
```

`requirements-mlflow.txt` records the complete updated tracking-test environment.
`tracking-constraints.txt` records the pre-existing versions held constant.
They describe this focused validation environment, not a replacement for
Goblet's complete Conda/CUDA environment.

## Results and scope

- Validation: macOS arm64, Python 3.10.19; separate environments for MLflow
  2.11.3 and 3.16.1. The 52 packages shared by the environments retain identical
  versions except MLflow. New MLflow dependencies are resolved separately.
- Key unchanged versions include NumPy 1.26.4, pandas 2.3.3, SciPy 1.13.1,
  scikit-learn 1.6.1, PyArrow 15.0.2 and protobuf 4.25.3.
- With 2.11.3 and the original training source: two compatibility tests passed;
  the explicit opt-out test was skipped because it is specific to MLflow 3.
- With 3.16.1 and the compatibility change: all three tests passed.
- The tests execute the actual MLflow statements extracted from `Model/train.py`
  against the real client, using deterministic, distinct scalar loss/accuracy
  fixtures. The training function itself is not imported or run.
- Four parameters, ten metrics with two steps each, run completion status,
  artifact name and artifact bytes match the old version's reference exactly.
- A portable file-store fixture was generated by MLflow 2.11.3 before changing
  `Model/train.py`. The new client reads its existing run with preserved IDs,
  start/end timestamps, original metric timestamps, params and artifacts.
  It can resume that run and append a metric without altering original values.
- Three tests cover new records, reading/resuming old records, and respecting
  an explicit file-store opt-out. `uv pip check` passes in both environments.
- OSV returned no advisories for MLflow 3.16.1 on 2026-10-02. This is a
  point-in-time package check, not a guarantee that all dependencies are safe.

## Not verified

Full DGL/PyTorch/CUDA training, Boltz-2 and molecular generation, the complete
Linux Conda environment, remote tracking servers, authentication, model serving
and database migration were not exercised. Existing vulnerabilities in other
pinned packages remain for separate changes. Pydantic 2.6.4 emits namespace
warnings when importing the updated MLflow; the tested tracking operations pass.
